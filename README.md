# 체험학습 운영실

2026년 11월 30일~12월 29일 체험학습 기간의 교사 임장과 출석을 함께 관리하는 한국어 웹앱입니다.

- 날짜를 가로 열, 교시를 세로 행으로 보는 A반·B반 교사별 임장표 조회·담당 변경·일정 맞교환
- 관리반·날짜·교시별 실제 출석 입력·수정, 메모와 변경 이력
- 선택한 날짜·관리반·교시의 저장된 기록 전체를 저장 전으로 복원
- 달력에서 운영일을 선택하여 교사 임장표와 교시별 출석 조회
- 원래 소속 반별 출석부 조회
- 달력에서 여러 운영일을 골라 학생 출석 명단에 한 번에 추가·즉시 취소
- 이메일 등록 없이 공용 비밀번호 하나로 접속

## 접속

일반 이용자는 전달받은 공용 비밀번호만 입력합니다. Firebase Authentication이 서버에서 비밀번호를 확인하고, 전용 공용 계정으로 인증된 접속에만 자료 접근을 허용합니다. 다른 이메일·비밀번호 계정을 임의로 만들거나 익명 로그인해도 자료를 읽을 수 없습니다. 관리자 유지보수는 고정된 Google 관리자 계정으로 구분합니다.

비밀번호는 공개 소스·공개 설정·웹페이지 파일에 넣지 않습니다. 별도로 전달받은 접속 안내 파일에서 확인하며, 해당 파일을 공개 저장소에 올리면 안 됩니다. 공개 설정에는 인증 계정의 공개 식별자와 내부 로그인용 이메일만 있습니다. 이용자가 이메일을 입력하거나 개인 회원가입할 필요는 없습니다.

공용 접속은 개인별 신원을 구분하지 않습니다. 변경 이력에는 개인 이름 대신 ‘공용 접속’으로 표시합니다. 비밀번호를 전달받은 모든 이용자가 같은 학생 명단과 출석 기록을 조회·수정하는 운영 방식을 전제로 합니다.

## 운영 기준

11월 30일·12월 1일은 두 관리반을 운영하고 이후에는 A반으로 통합합니다. 월·수·목은 6교시, 화·금은 7교시입니다. 14:00은 5교시 시작이며 반일 학생은 1~4교시 출석 예정, 이후 체험학습 예정입니다. 교시별 출석 입력은 출석·결석 두 가지만 사용하며, 토글 스위치를 클릭할 때마다 두 상태가 전환됩니다. 현재 상태는 스위치 옆 글자로도 표시합니다. 아직 저장한 기록이 없는 학생은 등교 예정 여부와 관계없이 결석을 기본 선택하며, 등교한 학생만 출석으로 바꿉니다. 반일 조퇴 이후에도 학생은 명단에 유지합니다. 실제 등교 여부에 따라 교사가 바꾼 뒤 선택한 날짜·반·교시의 기록을 저장합니다. 별도의 ‘해당 교시 예정’ 표시는 기존 체험학습 계획을 보여 줍니다. 기존 지각·조퇴 기록은 입력 화면에서 출석, 기존 체험학습 기록은 결석으로 표시하며 메모는 유지합니다. 화면을 여는 것만으로 기존 저장 자료가 변경되지는 않으며 저장할 때 두 상태로 반영됩니다. 저장한 출석·결석 상태와 메모는 기본값보다 우선하며, 원반별 출석부에는 확정해 저장한 기록이 표시됩니다. 주말, 12월 11일과 12월 25일은 제외합니다. 교사의 1·2학년 수업과 동시 임장은 배정할 수 없고, 지정된 임장 횟수 범위도 검사합니다.

실제 학생·교사 이름, 학생별 일정, 실제 기록과 초기 자료 파일은 이 저장소에 없습니다. 최초 관리자만 별도 초기 자료를 해시 검증 후 등록할 수 있으며, 기준 자료는 앱에서 덮어쓰거나 삭제할 수 없습니다.

## 공동 저장과 권한

학생 추가 창에서는 현재 화면과 다른 날짜도 여러 개 선택할 수 있습니다. 해당 학생이 이미 등록된 날짜와 미운영일은 선택할 수 없습니다. 11월 30일·12월 1일은 현재 관리반에, 이후 날짜는 A반에 추가합니다. 선택한 날짜는 ‘날짜별 등교 교시’ 표에서 날짜·요일·관리반·등교 시작·마지막 교시를 함께 확인하고 날짜마다 다르게 수정할 수 있습니다. 기본 종료 교시는 해당 날짜의 실제 마지막 교시인 6교시 또는 7교시이며, 한 날짜를 수정해도 다른 날짜의 교시는 바뀌지 않습니다. ‘첫 날짜 교시로 전체 적용’으로 같은 범위를 일괄 적용할 수 있으며 각 날짜의 운영 교시 범위 안에서 맞춥니다. 달력 아래 선택 목록에도 ‘11/30 · 1~4교시 · A반’처럼 범위를 표시합니다. 선택한 최대 20일을 한 트랜잭션으로 추가하므로 일부 날짜만 저장되지 않습니다. 원반별 출석부도 같은 명단을 사용합니다. 직후 ‘추가 취소’는 함께 추가한 날짜 전체에 적용하며 다른 기록이 저장된 뒤에는 취소를 차단합니다.

일괄 명단 이력은 `roster-batch`와 `entries: {date: "room:startPeriod:endPeriod"}`를 사용합니다. 보안 규칙은 실제로 변경되는 각 날짜의 학생·교시·관리반·한 학생만 변경·버전·작성자·시각과 이력 코드를 검증합니다. 이력은 대표 날짜의 실제 변경에 연결되며, 변경되지 않은 다른 날짜에 대한 이력 기재까지 모두 실제 쓰기였는지는 규칙만으로 보장하지 않습니다. 공식 클라이언트는 선택한 날짜 전체를 한 트랜잭션으로 쓰고, 실패하면 전체를 취소합니다. 이력의 모든 날짜와 범위 코드는 운영일 조회표와 유한한 허용 값으로 제한됩니다.

‘교시별 출석’의 ‘저장 전으로 복원’은 검색 결과와 관계없이 선택한 날짜·반·교시의 저장된 상태와 메모만 초기화합니다. 확인창에서 범위와 인원을 확인하며, 학생 추가 명단과 다른 날짜·반·교시 기록은 유지합니다. 복원 직후 알림의 ‘복원 취소’로 상태와 메모를 다시 살릴 수 있습니다. 확인 이후 다른 사용자의 변경이 먼저 저장되면 복원은 중단됩니다. 복원 뒤 입력창은 결석을 기본 선택하지만 실제 저장 기록은 미기록이며, 원반별 출석부에도 그대로 반영됩니다.

Firestore Enterprise Native의 전용 school-hub 데이터베이스, 서울(asia-northeast3), 무료 Spark 계획을 사용합니다. 실시간 공동 편집 때문에 Core SDK의 onSnapshot과 트랜잭션을 사용합니다. 현재 버전과 변경 이력을 함께 저장하여 동시 변경으로 기존 내용을 덮어쓰지 않게 합니다.

school/config는 최초 기준 자료와 학생 ID 조회표, school/schedule은 임장 배정, school/live는 버전, attendance는 교시별 출석, dailyRosters/{date}는 날짜별 추가 등교 명단, history는 변경 이력입니다. 추가 명단은 원래 신청 일정과 분리하며 출석 화면과 원반별 화면이 같은 명단을 사용합니다. 추가한 뒤 해당 교시의 출석을 저장하면 원반별 출석 기록에도 함께 표시됩니다. 다른 변경이 저장되기 전에는 즉시 ‘추가 취소’가 가능하고, 저장된 기록을 가리는 취소는 차단합니다. 지우기는 삭제 대신 되돌릴 수 있는 미기록 상태로 저장합니다. 인증된 작성자·자료형·허용 필드·해당 학생·날짜·교시·교사 수업·배정 횟수·현재 버전을 서버에서 검사합니다.

security/shared에는 enabled, validAfter, updatedAt, updatedBy만 있습니다. Google 관리자만 접속을 일괄 중지하거나 auth_time 기준으로 이전 세션을 차단할 수 있습니다. 이 문서에 비밀번호나 비밀번호 해시는 없습니다. 예전 access 이메일 목록은 더 이상 자료 접근 권한을 부여하지 않으며, 앱에서 교사 이메일을 등록하지 않습니다.

I've set up prototype Security Rules to keep the data in Firestore safe. They are designed to be secure for this shared-password workspace because Firebase verifies the password, data access is pinned to one dedicated authenticated UID, privileged configuration requires the Google owner, and data edits retain validation and revision checks. However, you should review and verify them before broadly sharing your app. If you'd like, I can help you harden these rules.

## 개발과 검증

Node.js 24와 Java 21에서 다음 명령을 실행합니다.

~~~sh
npm ci
npm test
npx --yes firebase-tools@15.36.0 emulators:exec --project demo-school-hub --only firestore --config firebase.emulator.json "node scripts/test-shared.mjs"
npm run build
npm run dev
~~~

통합 검증은 매번 새로운 demo-school-hub-* Enterprise 에뮬레이터 프로젝트와 가상의 인물만 사용합니다. 실제 운영 자료나 운영 비밀번호는 사용하지 않습니다. 올바른 전용 인증 계정과 잘못된 인증 계정, 28명 일괄 출석, 같은 공용 계정의 두 브라우저 동시 저장, 임장 변경·맞교환, 추가 학생 동기화·출석·즉시 취소, 중복 등록과 잘못된 학생·교시·관리반 차단, 기록 위조 차단, 접속 중지와 이전 세션 차단을 검사합니다.

관리자와 공용 계정 UID를 변경하면 공개 연결 설정을 수정한 뒤 node scripts/generate-rules.mjs로 규칙을 다시 생성합니다. 규칙 배포에는 별도로 인증한 프로젝트 관리자가 필요하며 GitHub Actions에 관리자 자격 증명이나 운영 비밀번호를 넣지 않습니다. 비밀번호 교체는 Firebase 관리자 권한으로 수행하고 security/shared의 validAfter를 갱신하여 이전 세션도 차단해야 합니다.
